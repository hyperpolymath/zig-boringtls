= Proof Status — zig-boringtls

This is the repository's proof-status file in the sense of
`3-practice/PROOF-POLICY.adoc` §8.5 (`metadatastician/standards`): one row
per claim, with its status token, its Proof Witness Grade (PWG) and its
recheck legs. The estate census (hyperpolymath/mathesis) reads this file. A
row says only what a receipt or a gate supports. There is no percentage or
overall figure (§8.4).

== Vocabulary

* *Status token* (§5): `proven`, `proven-with-postulates`, `tested-only`,
  `argued`, `open`.
* *PWG* (§8) grades *theory* theorems only. This repository has no theory
  obligations (PROOF-NEEDS.adoc), so every row with a result is `n/a`, and an
  `open` row is `ungraded`.
* *Recheck legs* (§2) apply to theory only, so they are `n/a` throughout.

== Trust boundary

* *BoringSSL* (`0.20260929.0`, tag commit `427ec40c`): an `ASSUMED` boundary
  (§1.1). The handshake state machines, record protection, cryptography and
  X.509 validation are BoringSSL's; `docs/security/TLS-WRAPPER-SECURITY.adoc`
  §1 lists what is taken from it. No claim above depends on it: LIN-1 to LIN-3
  are about the contract, not the library.
* *Idris2 0.7.0*: its elaborator and quantity (QTT) checker are trusted for
  LIN-1 to LIN-3. A `failing` block is a claim that elaboration fails with the
  stated error, so LIN-2 trusts the same checker to reject.
* *Deviation (§6), state `open`*: Idris2 was built from source in an agent
  session (tag `v0.7.0`, commit `27780073`, with Debian Chez Scheme
  `9.5.8`), not installed from the Guix manifest or the
  container, and no CI lane runs `just proof-check-idris2` yet. Closing it
  means provisioning Idris2 through Guix or the container and adding the
  lane.

----
just proof-check-idris2                          # scripts/check-proofs.sh idris2
(cd src/interface && idris2 --typecheck abi.ipkg)

`proof-check-coq` and `proof-check-lean4` report "nothing to check".
