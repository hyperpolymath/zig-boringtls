= Proof Requirements — zig-boringtls

Which prover carries which obligation is set by
`3-practice/PROOF-POLICY.adoc` §1 in `metadatastician/standards`; where this
file and the policy differ, the policy wins.

zig-boringtls is a thin Zig wrapper over BoringSSL. Its obligations are
*engineering* ones: they name types and functions of this repository, so they
go to Idris2 (§1). It has *no theory obligations*: nothing here would be true
of any implementation, so there is no Agda source and no Rocq or Lean recheck
leg. Cryptography, the TLS state machines and X.509 validation are BoringSSL's,
recorded as an `ASSUMED` boundary (§1.1), not re-proved.

== Proof tier

*Tier*: T2 — High (proposed, owner to confirm). This is the TLS layer under
the estate's DoH, DoQ and Gemini clients; a misuse here is a security defect
downstream.

== Template ABI proofs (ABI-1 to ABI-5)

The template marks five ABI proofs (non-null pointers, layout, platform sizes,
FFI return types, C ABI compliance) as mandatory. They are proofs about a C
ABI the repository *exports*. zig-boringtls exports none: it wraps C, it does
not export it (issue #11). They become applicable when #11 decides the export,
and are recorded as not applicable until then rather than kept as template
files that prove nothing about this code.

== Banned patterns

None of these may appear in a proof file: `believe_me`, `assert_total`,
`postulate`, `sorry`, `Admitted`, `unsafeCoerce`, `Obj.magic`. Idris2 modules
use `%default total`.
