= AI-Assisted Installation Guide
:toc:
:toclevels: 3
:sectnums:

This guide is for an **AI agent** setting up zig-boringtls to build and test
it, or to use it from another Zig project. A human can follow it too. The
ordering and the warnings are written for an agent working without
supervision.

[[ai-implementation]]
== Implementation for an AI agent

=== 1. Orient before acting

Read these files in this order before running anything:

. `zig-boringtls_chora.deed`, the repo deed: what this repository IS and IS NOT.
. `CLAUDE.md`, the generated arrival pack: estate doctrine and repo identity.
. `docs/security/TLS-WRAPPER-SECURITY.adoc`, which says what the wrapper does
  and does not guarantee. Do not describe this library as "secure".

=== 2. Clone

[source,bash]
----
git clone https://github.com/hyperpolymath/zig-boringtls.git
cd zig-boringtls
----

=== 3. Install the toolchain (per user, checksum-verified)

The build needs Zig **0.17.0** exactly. The test fixtures need `bash` and
OpenSSL 3.x. Nothing else is required: BoringSSL is fetched and
hash-verified by the Zig package manager, and compiled by `build.zig`.

[source,bash]
----
curl -fsSLo zig.tar.xz https://ziglang.org/download/0.17.0/zig-x86_64-linux-0.17.0.tar.xz
echo "1cbe9df9f27e6b78d14ccbca43b6703a404ef79ef1c463de901d7f088d4e2026  zig.tar.xz" | sha256sum -c -
tar -xf zig.tar.xz && export PATH="$PWD/zig-x86_64-linux-0.17.0:$PATH"
----

Stop if the checksum does not match. Do not substitute another Zig version.

=== 4. Build and test

[source,bash]
----
cd src/interface/ffi
zig build test --summary all        # expect 37/37; the first build compiles BoringSSL (minutes)
./scripts/mutation-check.sh         # expect "all mutations behaved as expected"
./scripts/ffi-drift-selftest.sh     # expect "all injected drifts caught"
----

Report the exact summary lines. If `zig build` refuses the BoringSSL package
with a hash mismatch, stop and report it. Do not edit the hash in
`build.zig.zon` to make the build pass, because that hash is the supply-chain
pin.

=== 5. Use from another Zig project

There is no tagged release yet. Point a path dependency at
`src/interface/ffi/` and import the `boringtls` module. Read the usage
examples in `README.adoc` before choosing a `Trust` mode.

== Privacy

Setting up and testing zig-boringtls sends no telemetry. The only outbound
requests are:

* the Zig download from ziglang.org;
* the BoringSSL tarball from GitHub, which the Zig package manager verifies
  against the content hash in `build.zig.zon`.

The tests run entirely over loopback. Their certificates and private keys are
generated into the build cache on every run and never leave the machine.
